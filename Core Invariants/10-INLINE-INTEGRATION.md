# ARTOON Inline Integration System

**نظام التضمين الداخلي**

---

## 1. المبدأ الأساسي

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│   البنية تُكتب على مستوى السطر                                         │
│   المعنى يُثرى داخل السياق                                             │
│                                                                         │
│   التضمين الداخلي = دلالي وليس بنيوي                                   │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

**لماذا نحتاج التضمين الداخلي؟**

المحتوى الحقيقي نادراً ما يكون نصاً صرفاً:
- نشير إلى مصادر
- نُدرج رموزاً
- نُلمّح إلى صور أو ملفات
- نضيف اختصارات أو تواريخ

**منع التضمين** = صيغة فقيرة
**السماح بلا ضوابط** = HTML متنكر

---

## 2. نوعا التصريح في ARTOON

### 2.1 التصريح البنيوي (Structural Declaration)

يُكتب على مستوى السطر:

```artoon
>.img:: photo.jpg
>.ul::
>.table::
```

**معناه:**
- إنشاء كيان دلالي مستقل
- فتح سياق جديد
- يمكن فصله، نقله، أو إعادة ترتيبه

**هذا هو مستوى البنية.**

### 2.2 التصريح الداخلي (Inline Declaration)

يُكتب داخل سياق مفتوح بين أقواس:

```artoon
[img:: icon.svg]
[a:: https://example.com; مصدر]
```

**معناه:**
- توصيف سياقي مرتبط بالنص المحيط
- لا يُنشئ كيانًا مستقلًا
- لا يفتح سياقًا جديدًا
- تفسيره متروك للعارض (Renderer)

**هذا هو مستوى المعنى.**

## 4. المكونات المسموح تضمينها داخلياً

### 4.1 القائمة الكاملة

هذه المكونات تُعد **واصفات دلالية** وليست بنى:

| المكون | الوصف | مثال |
|--------|-------|------|
| `a` | إحالة نصية | `[a:: url; نص]` |
| `img` | مرجع بصري سياقي | `[img:: icon.svg]` |
| `audio` | إشارة صوتية | `[audio:: sound.mp3]` |
| `video` | إشارة مرئية | `[video:: clip.mp4]` |
| `file` | مرجع ملف | `[file:: doc.pdf]` |
| `abbr` | اختصار | `[abbr:: AI; Artificial Intelligence]` |
| `time` | زمن أو تاريخ | `[time:: 2026-01-05]` |
| `c` | كود سطري | `[c:: code]` |
| `s` | أهمية قوية | `[s:: مهم]` |
| `e` | تأكيد | `[e:: مؤكد]` |
| `u` | تسطير | `[u:: مسطر]` |
| `d` | شطب | `[d:: محذوف]` |
| `mark` | تمييز | `[mark:: مميز]` |
| `sub` | نص منخفض | `[sub:: 2]` |
| `sup` | نص مرتفع | `[sup:: 2]` |

### 4.2 مثال شامل

```artoon
>.p:: هذا النص يشير إلى [a:: https://example.com; هذا المصدر] ويحتوي [abbr:: AI; Artificial Intelligence] ومدعّم بـ [img:: icon.svg].
```

## 5. المكونات الممنوع تضمينها داخلياً

### 5.1 القائمة الكاملة

هذه المكونات تُعد **بنى** لا توصيفات:

| المكون | السبب |
|--------|-------|
| `ul`, `ol`, `dl` | قوائم = بنى متعددة العناصر |
| `table` | جدول = بنية صفوف وأعمدة |
| `figure` | مكون مركب = بنية |
| `details` | مكون مركب = بنية |
| أي بلوك | البلوكات = حاويات بنيوية |

### 5.2 مثال خاطئ

```artoon
✗ خطأ:
>.p:: هذا نص [ul:: li:عنصر]

السبب: محاولة إنشاء بنية داخل سياق لغوي
```

## 6. نظام المُعدِّلات (Modifier System)

### 6.1 القاعدة الأساسية

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│   المُعدِّلات (Modifiers) للنصوص فقط                                   │
│                                                                         │
│   s, e, u, d, mark, sub, sup                                           │
│                                                                         │
│   تُعدِّل طريقة عرض النص                                               │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 6.2 ما هو المُعدِّل (Modifier)؟

المُعدِّل = **حالة تُعدِّل طريقة عرض النص** تُضاف قبل نوع المكوّن.

**المُعدِّلات هي:**
- `s` — أهمية قوية (strong)
- `e` — تأكيد (emphasis)
- `u` — تسطير (underline)
- `d` — شطب (deleted)
- `mark` — تمييز (highlight)
- `sub` — نص منخفض
- `sup` — نص مرتفع

### 6.3 المكونات التي تقبل المُعدِّلات

| المكون | يقبل مُعدِّلات؟ | السبب | مثال |
|--------|---------------|-------|------|
| نص | ✓ | نص | `[s:: مهم]` |
| `a` | ✓ | الرابط نص | `[s+a:: url; رابط مهم]` |
| `abbr` | ✓ | الاختصار نص | `[mark+abbr:: API; ...]` |
| `time` | ✓ | التاريخ نص | `[s+time:: 2026-01-05]` |
| `img` | ✗ | ليس نصاً | — |
| `audio` | ✗ | ليس نصاً | — |
| `video` | ✗ | ليس نصاً | — |
| `file` | ✗ | ليس نصاً | — |
| `c` | ✗ | يُعرض كما هو | — |

### 6.4 الصيغة العامة

```
[modifier+modifier+type:: value]
```

### 6.5 أمثلة صحيحة

```artoon
✓ [s+a:: https://example.com; رابط مهم]
✓ [u+a:: https://example.com; رابط مسطر]
✓ [s+e+a:: https://example.com; رابط مهم ومؤكد]
✓ [mark+abbr:: CSS; Cascading Style Sheets]
✓ [s+time:: 2026-01-05; تاريخ مهم]
✓ [e+time:: 2026-01-05]
```

### 6.6 أمثلة خاطئة

```artoon
✗ [s+img:: photo.jpg]      ← الصورة ليست نصاً
✗ [mark+audio:: sound.mp3] ← الصوت ليس نصاً
✗ [u+video:: clip.mp4]     ← الفيديو ليس نصاً
✗ [e+file:: doc.pdf]       ← الملف ليس نصاً
✗ [s+c:: code]             ← الكود يُعرض كما هو
```

### 6.7 لماذا الروابط تقبل المُعدِّلات؟

```
الرابط = نص + وجهة

[a:: url; نص الرابط]
         ↑
      هذا نص!

لذلك:
[s+a:: url; نص مهم] = رابط بنص مهم
[u+a:: url; نص مسطر] = رابط بنص مسطر
```

## 8. البنى كسياقات مفتوحة

رغم أن البنى لا تُكتب داخلياً، إلا أنها:
**تفتح سياقاً يسمح بالتضمين الداخلي داخل محتواها.**

### 8.1 داخل القوائم

```artoon
>.ul::
li:: عنصر يحتوي [a:: https://x.com; رابط]
li:: عنصر مع [img:: star.svg]
li:: عنصر بـ [abbr:: API; Application Programming Interface]
```

### 8.2 داخل الجداول

```artoon
>.table::
th:: الاسم; الوصف
tr:: علي; نص مع [abbr:: AI; Artificial Intelligence]
tr:: سارة; تاريخ [time:: 2026-01-05]
```

### 8.3 داخل المكونات المركبة

```artoon
>.details:: اقرأ المزيد
>.-p:: محتوى مع [a:: https://docs.com; رابط للوثائق]
>.-p:: وأيضاً [img:: icon.svg] كمرجع بصري
```

**لا يوجد هنا تداخل بنيوي، بل إثراء دلالي.**

## 9. أمثلة عملية شاملة

### 9.1 فقرة غنية

```artoon
>.p:: في [time:: 2026-01-05; يناير 2026] أطلقنا [abbr:: ARTOON; Advanced Rich Text Object Oriented Notation] وهي [s:: ثورة] في عالم [e:: المحتوى الدلالي]. اقرأ [s+a:: https://docs.artoon.dev; الوثائق] لمعرفة المزيد.
```

### 9.2 قائمة مع تضمينات

```artoon
>.ul::
li:: [s:: مهم]: اقرأ [a:: https://guide.com; الدليل] أولاً
li:: استخدم [c:: npm install artoon] للتثبيت
li:: آخر تحديث: [time:: 2026-01-05]
li:: الشعار: [img:: logo.svg]
```

### 9.3 جدول مع تضمينات

```artoon
>.table::
th:: المكون; الوصف; الحالة
tr:: Parser; يحلل [abbr:: AST; Abstract Syntax Tree]; [s:: مكتمل]
tr:: Renderer; يعرض [abbr:: HTML; HyperText Markup Language]; [e:: قيد التطوير]
tr:: Editor; محرر [a:: https://studio.artoon.dev; ARTOON Studio]; [mark:: جديد]
```

### 9.4 روابط مع مُعدِّلات

```artoon
>.p:: هذا [s+a:: https://important.com; رابط مهم جداً] يجب قراءته.
>.p:: انظر [u+a:: https://reference.com; المرجع] للتفاصيل.
>.p:: تحذير: [d+a:: https://old.com; الرابط القديم] لم يعد يعمل.
>.p:: اقرأ [mark+a:: https://highlight.com; هذا الرابط المميز] أولاً.
```

## 10. ملخص للمبرمجين

### 10.1 لماذا هذا النموذج مهم؟

```
✓ Parser بسيط (لا تداخل بنيوي)
✓ AST واضح (بنية vs توصيف)
✓ حرية كاملة في العرض
✓ قدرة على إعادة التفسير حسب المنصة
✓ النية مُشفّرة دلالياً (لا تخمين)
```

### 10.2 خلاصة تنفيذية

```
┌─────────────────────────────────────────────────────────────────────────┐
│                                                                         │
│   1. البنية تُكتب كسطر مستقل                                           │
│   2. التضمين الداخلي للمكونات الدلالية فقط                             │
│   3. المُعدِّلات للنصوص فقط (s, e, u, d, mark, sub, sup)              │
│   4. الروابط نصوص → تقبل المُعدِّلات                                   │
│   5. الميديا (img, audio, video, file) ليست نصوص → لا مُعدِّلات       │
│   6. الكود (c) يُعرض كما هو → لا مُعدِّلات                             │
│   7. المُعدِّل قبل النوع دائماً                                        │
│   8. لا بنى داخلية                                                     │
│   9. البنى تسمح بالتضمين داخلها                                        │
│                                                                         │
│   إذا التزمت بهذه القواعد:                                             │
│   • لن يتحول ARTOON إلى HTML                                           │
│   • لن يُفقِر المحتوى                                                  │
│   • سيبقى قابلاً للتطور طويلاً                                         │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```
